# Platform no-parameter token response: mock contract candidate

This isolated branch now includes the full candidate chain: live host ID/token capture, same-origin client header, existing UUID Worker forwarding gate, backend per-request subject check, and original account-owner derivation. It is **off in the default build and configuration**. No real token, platform request, account lookup, or player save is involved.

The user's Wang Xing relay gives the exact endpoint `GET https://aigram.aiwaves.tech/note/wallet/aigram/get/alteru/window/info`, with the live token in request header `token` and **no telegramId parameter**. Its `data.telegram_id` is the token subject to compare with live `window.Aigram.id`. The browser sends the token to the same-origin Worker as `Authorization: Bearer` under the candidate gate; the backend strips that internal wrapper and sends only the raw value in platform header `token`. The probe requires HTTP 200, JSON `retcode === 0`, JSON `errcode === 0`, and a decimal-string `data.telegram_id` identical to the live ID. It never converts an ID to a JavaScript number. The mock includes `9007199254740993` to catch precision loss.

The default `VITE_HARBOR_PLATFORM_TOKEN_MODE` is unset, so the client retains the published temporary path and drops any caller Authorization. The candidate requires that build switch, Worker `HARBOR_IDENTITY_MODE=platform-verified-v1` and `HARBOR_PLATFORM_TOKEN_MODE=candidate-token-owner-v1`, plus backend identity mode and token mode. None of these were changed on a live service. The Worker uses a fixed non-identity edge placeholder; only the backend derives the old owner hash after a fresh self-subject match. No journey migration is performed.

The tests pin the exact URL, raw `token` header and absent query; they also cover mock success/failure, arbitrary token subject mismatch, error status, retcode, errcode, non-JSON/oversized responses, timeout, Worker gates, and one synthetic SQLite old-journey read. Actual platform response examples, token expiry/revocation behavior, and three real host lifecycles remain for platform/pre-release acceptance. This candidate must not be published or switched on from the mock evidence alone.
